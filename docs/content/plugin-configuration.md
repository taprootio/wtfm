## Required manifest input {#required-manifest-input}

`cemPath` identifies the Custom Elements Manifest read when the plugin is
configured. Use an absolute path or a path relative to the process working
directory. A missing or unreadable file produces an empty manifest with a
warning; projects that require generated references should make manifest
generation and validation explicit earlier build steps.

```js
eleventyConfig.addPlugin(wtfmPlugin, {
  cemPath: "custom-elements.json",
});
```

## Optional data inputs {#optional-data-inputs}

`typeManifestPath` adds interfaces, type aliases, functions, and other
non-element declarations generated by WTFM's type extractor. `assetsDir`
controls where the `inlineSvg` shortcode reads SVG source. Neither path is a
publishing destination.

The plugin exposes `customElements`, `docSurfaces`, and, when configured,
`typeManifest` as global Eleventy data.

## Renderer selection {#renderer-selection}

`sections` sets the default ordered renderer keys. Built-in component sections
include examples, slots, attributes, methods, events, CSS parts, and CSS custom
properties. The aliases `cssparts` and `cssprops` resolve to their canonical
keys.

```js
eleventyConfig.addPlugin(wtfmPlugin, {
  cemPath: "custom-elements.json",
  sections: ["examples", "attributes", "events", "css-properties"],
});
```

A declaration's `@docSections` tag can replace that order or use `all` and
negative entries such as `-methods`. `customRenderers` registers additional
renderer objects by key; a custom renderer with a built-in key replaces that
renderer. Keep custom output compatible with every rendering mode it is asked
to support.

## Filtering attributes {#filtering-attributes}

`excludeAttributes` removes inherited or internal attributes globally.
`attributeExceptions` maps an excluded attribute to the tag names where it
remains public.

```js
{
  excludeAttributes: ["scheme"],
  attributeExceptions: { scheme: ["example-root"] },
}
```

An exception key must also be excluded globally; keeping the relationship
explicit prevents a configuration typo from changing public reference output.

## Surface routes and source links {#surface-routes-and-source-links}

`referenceUrlBuilder` and `helpUrlBuilder` own the canonical routes for each
validated documentation surface. Stable slugs and stable route builders are
link contracts. When a route changes, add an external redirect rather than
changing a resource identity.

`githubLinkTemplate` customizes the visible link made from a declaration's
`github` metadata. It receives the already-derived URL and returns site HTML;
the semantic Taproot Docs path records a plain source location separately.

## Taproot Docs options {#taproot-docs-options}

The optional `taprootDocs` block enables semantic output. It requires complete
GitHub source provenance and an ordered navigation tree. Locale, shared assets,
an asset root, and a deterministic source epoch are optional. The stable
repository id is never inferred from the owner/name locator.

See [Taproot Docs artifact mode](/artifact-mode/) for the full example and
failure model.
