# WTFM0012 - Make rendered math deterministic across builds

## The finding

Taproot's TR00595 prebuilt-Docs dogfood proved that an Eleventy site using
wtfm cannot produce byte-deterministic builds when its pages render math.
wtfm's plugin wires `markdown-it-mathjax3`, whose `mathxyjax3` dependency
scopes every rendered TeX block with

```js
`mjx-${Math.random().toString(16).substring(8)}`
```

— a fresh id on every render, written twice per block (the wrapper's `id`
attribute and the `#id` selector opening its scoped `<style>`), and
**variable in length** (the hex tail of `Math.random()` is 6–9 characters),
so even byte counts drift between builds. In taproot-controls, nine guide
pages embedding math hashed differently on every build, and Pagefind's
content-hashed fragment filenames churned with them — which broke the
prebuilt Docs contract's requirement that two clean builds of one source
revision produce identical bytes.

taproot-controls now carries a site-side Eleventy transform (ESP0170,
`scripts/normalize-mathjax-ids.js`) that renumbers the ids per page to
`mjx-eq-1`, `mjx-eq-2`, … in document order. That transform is deliberately
written to become a stable no-op the day wtfm renders deterministically —
this task is that day's work, in the layer where every consumer benefits.

## Scope

- Make the ids wtfm's rendered math emits deterministic per document: a
  per-document counter (or content-derived id) applied where wtfm invokes
  or post-processes `markdown-it-mathjax3`, so the same source renders the
  same bytes on every build. Rewrite both occurrences per block — the `id`
  attribute and the matching `#id` style selector — and nothing else; the
  MathJax element/class vocabulary (`mjx-container`, `mjx-assistive-mml`,
  glyph tokens) is not id-anchored and must survive verbatim.
- Guard against prefix collisions when rewriting (one generated id can be a
  strict prefix of another) and leave non-generated `mjx-*` ids alone.
- Cover it with a determinism test: rendering the same math-bearing source
  twice yields identical bytes, and two blocks on one page get stable,
  distinct ids.
- Consider upstreaming: `mathxyjax3` (tani/mathxyjax3) generates the random
  id in its tex2svg wrapper; a small upstream PR making the id injectable or
  counter-based would let wtfm drop its own handling later. Optional here —
  wtfm must be deterministic regardless of upstream latency.

## Out of scope

- taproot-controls' ESP0170 transform. It stays until a wtfm release with
  this fix is adopted there, then becomes a no-op and can be retired by that
  repository on its own schedule.
- Determinism sources other than math ids. No other nondeterminism was
  observed in the dogfood's builds once math ids were normalized.

## Acceptance criteria

- Two builds of one revision of a math-bearing wtfm site produce identical
  rendered bytes for every math block, with no site-side normalization.
- The rendered visual output is unchanged — the id is a page-local scope
  handle, so renumbering it is a rename, not a rewrite.
- A regression test pins the determinism and fails on a reintroduced
  random id.
