# WTFM0010 - Emit Taproot Docs artifacts from the Eleventy build

The producer half of Taproot's Docs artifact contract (Taproot TR00456;
contract defined by TR00455, released via TR00571 as
`@taprootio/docs-artifact@1.0.1`). Taproot ingests only the manifest and the
files it lists — never scraped page HTML — so this mode is additive and the
normal portable `_site` output is byte-for-byte unaffected when disabled and
still fully portable when enabled.

## Scope

- Add `@taprootio/docs-artifact` as an **exact** `"1.0.1"` runtime dependency
  (no range; producer and consumer pin the same released contract).
- Add an opt-in `taprootDocs` plugin configuration block. When absent, build
  output is unchanged. When present, an `eleventy.after` emitter writes
  `_site/taproot-docs-manifest.json` plus `_site/taproot-docs/fragments/` and
  `_site/taproot-docs/assets/`, serialized with `serializeManifest` and
  asserted with `assertValidManifest` — never a hand-built JSON shape.
- **Semantic fragment boundary:** fragments are produced only by a dedicated
  semantic rendering path constrained to the contract's closed markup set.
  Rendered `_site` HTML files are never treated as fragments.
  - Authored documents opt in per page via a `taprootDocs` front-matter block
    with a required explicit resource `key` and semantic `kind` (plus optional
    audiences, tags, description, `redirectsFrom`, and declared assets).
    Missing, malformed, or duplicate keys fail the build; keys are never
    derived from routes, titles, or file paths.
  - Surface reference pages emit `reference:<surface-slug>` resources through
    a semantic variant of the section renderers (plain `<pre><code>`, no
    `<wtfm-code-block>`, no class-dependent markup), keyed by the existing
    explicit, duplicate-checked surface slugs.
- Derive per-variant route, title, description, ordered heading inventory
  (reusing the WTFM0004 anchor pipeline), and source path/URL (via the
  existing GitHub link seam) deterministically; single configured default
  locale in v1. Cross-document links use `data-resource-key` markup resolved
  from explicit targets, and images resolve to declared assets via
  `data-asset-key` — never raw routes or file paths.
- Navigation comes from an explicit `taprootDocs.navigation` config tree
  referencing resource keys, validated against emitted keys.
- Provenance fails closed: `source.*` (GitHub stable repository id, locator,
  revision, ref) from explicit configuration or opt-in CI env — the stable
  repository id is never inferred; `build.*` with producer/version,
  `configurationSha256` over the resolved docs-mode configuration, and
  `sourceDateEpoch` from SOURCE_DATE_EPOCH or the HEAD commit timestamp —
  no wall-clock values.
- Assets: only explicitly declared files are copied under
  `taproot-docs/assets/`; reject traversal/absolute/duplicate paths, missing
  files, undeclared media types, and hash drift between declaration and bytes.
- Redirects come only from explicit `redirectsFrom` declarations and target
  resource keys, per the contract's no-chain construction.
- Add a small real Eleventy fixture project (modeled on
  `__tests__/fixtures/eleventy-path-prefix/`) that builds with the mode on,
  and a CI-suitable conformance command that runs the fixture build through
  `validateArtifactDirectory` and `loadConformanceCases` — no duplicated
  contract logic in WTFM.
- Tests: byte-identical manifests across repeated builds (determinism);
  fail-closed cases (missing key, duplicate key, unsafe asset path, missing
  asset, invalid redirect, hash drift, missing provenance, wrong schema
  config); ordinary-site preservation with the mode off and on; fixture
  conformance green.
- Release readiness: bump to 0.16.0 with CHANGELOG entry. Publishing the
  release and Taproot-side consumption stay outside this task (Taproot
  TR00456 remains open until it consumes the released version).

## Notes

- Cross-repo: Taproot TR00456 owns consumption readiness; TR00455/TR00571
  define and distribute the contract. Cross-repo ids in prose only.
- ESP0119 help documents are Taproot-app help surfaces, not public docs-site
  content — out of scope here.
- Canonical manifest routes are site-root-relative page URLs (pathPrefix-free)
  normalized through the package's `normalizeRoute`.

## Risks

- Non-deterministic output defeats upload dedup and makes release diffs noisy;
  identity derivation changes after launch need a migration story (mirrors
  TR00456).
- The semantic reference-surface renderer is the largest new surface; markup
  outside the closed set must fail the build, not silently pass through.
