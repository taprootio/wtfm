# WTFM0014 — Republish WTFM Docs so both retained production releases carry redirect markers

## Why

Taproot's TR00968 serves published-site redirects only from redirect markers
stored with each release. WTFM's current and previous production Docs releases
(2026-09-17 and 2026-09-13) were built before Docs releases carried markers, and
both froze two redirects with no markers. Taproot keeps two Docs releases per
site (current and previous), so both had to be replaced.

## What changed

Nothing in WTFM's content or code. Each merge to `main` runs **Publish Taproot
Docs**, and a Docs release's identity includes the source commit, so each merge
produced a new production release rendered with markers:

1. [#26](https://github.com/taprootio/wtfm/pull/26): an empty commit (publish run
   36662060691).
2. The pull request that adds this record: the second publish.

## Verification

Taproot's read-only `scripts/republish-marker-check.sql`, run against production
after the second publish, must no longer list WTFM in its first result set.
